## A. AI Workloads, HBM4, HBF, CXL & 5-Tier Memory-Storage Hierarchy

- **Four AI Storage Phases:** Ingest/Prep (ultra-dense QLC lakes like UltraQLC), Model Training (`>90%` GPU util via NVIDIA GDS `cuFile`/`cuObject`), Checkpointing (bursty sync writes every 15–30 min across 8B–1.25T models), and Inference KV-Cache Offloading.
- **LLM KV-Cache Scaling Formula:**
  `KV Cache Size (GB) = (2 * B * S * L * H * D * (Q / 8)) / 1024^3`
  - Example: Llama 3.1 70B @ 128K context ≈ **40 GB/user** -> 8 concurrent users ≈ **320 GB** (`4x` an 80 GB H100's entire HBM), driving tiered offload across `HBM -> DDR5 -> NVMe / CXL / HBF` (vLLM, SGLang HiCache, LMCache, Mooncake, NVIDIA Dynamo KVBM + NIXL).
  - **MLPerf Storage v3.0** (Sept 1, 2026; 19 orgs, 143 results) adds dedicated KV Cache and Vector Database benchmarks alongside U-Net3D/RetinaNet training and checkpointing.
- **HBM4 vs. SanDisk/SK hynix HBF:**
  - **HBM4** (JEDEC JESD270-4/4A): 2,048-bit bus, 32 channels, up to 64 GB & 2 TB/s JEDEC baseline/stack (vendor silicon 2.8–3.3 TB/s) + Directed Refresh Management.
  - **HBF** (OCP High-Level Base Die Spec v0.7.0, Aug 2026): 8-layer (256 GB) & 16-layer (512 GB) NAND stacks across 3 UCIe tiers (`384 GB/s` to `3.072 TB/s`); SanDisk simulation reported Llama 3.1 405B weight reads within `2.2%` of unlimited HBM. **Hot Chips 2026 caveat (OXMIQ Labs):** NAND latency & write endurance restrict general workloads—HBF excels for massive read-dominant datasets (MoE weights, long context caches) behind an HBM4 hot tier.
- **CXL 3.x / 4.0 & Linux Tiering:** CXL 3.0/3.1 (64 GT/s, multi-level switching, coherent sharing) and CXL 4.0 (128 GT/s, bundled ports, enhanced RAS). Type 3 modules (often E3.S 2T) appear as CPU-less NUMA nodes at `~170–250 ns` (~70 ns above local DDR5 JESD79-5D `~80–110 ns`). Linux classifies tiers under `/sys/devices/virtual/memory_tiering/memory_tierN/` using `kswapd`/DAMON (`DAMOS_MIGRATE_COLD`) + NUMA balancing. Meta's **CacheLib** supports NVMe FDP directly; dual-mode SSDs (Phison Mixed Media, DapuStor J5060) expose separate pSLC/QLC endurance groups.

## B. Enterprise DBs, Fabrics, Computational Storage & Gaming

- **Databases + FDP:** Mapping RocksDB/MySQL write classes to NVMe FDP RUHs (XFS hinting, KIOXIA UFROP, Samsung TorFS): academic study achieved near-`1.0` RocksDB WAF at 90% fill; Samsung reported `-30%` WAF, `+10%` OPS, `-55%` p99.9 latency; DapuStor reported `+22.4%` frontend write throughput on R6101. Also track **Ceph Crimson / PoseidonStore** (`io_uring` sharded backend) and parallel filesystems (Lustre, WEKA, DDN EXAScaler).
- **NVMe-oF Fabrics:** **NVMe/TCP** (`100–400 µs` over standard Ethernet; tuning `-i` queues dropped latency `>42%` in a Lightbits test raising `-i` 8→96; plus Linux `kTLS 1.3` & zero-copy/DDP) vs. **NVMe/RoCEv2** (`20–100 µs` over UDP 4791 zero-copy RDMA, paired with lossless `PFC + ECN/DCQCN`).
- **Computational Storage & Gaming:** SNIA CS-APM v1.2 + NVMe Computational Programs (TP4091) / SLM (still gated by standardized host discovery/programming models). Gaming (SN8100 / Optimus): QD1–QD4 4K random reads, nCache 4.0 folding, Microsoft **DirectStorage 1.2+** (BypassIO + GPU GDeflate/experimental ZSTD; console/GDK targets 50,000 IOPS at `≤10%` of 1 core & `2.0 GB/s` min over 250 ms windows).

## C. Storage Security Validation

- **TCG Storage Core 2.01 & Opal 2.30:** Level 0 Discovery, multiple LBA Locking Ranges, Admin/User authorities, Shadow MBR PBA, mandatory Block SID & PSID Revert, cryptographic erase; plus **TCG Ruby 1.00** (data center profile) and **Aug 2026 Epoch Key Purge (EKP)**.
- **Hyperscale Platform Attestation:** **OCP S.A.F.E.** (20 assessment areas, X.509 PKI, mandatory in OCP 2.6) and **OCP L.O.C.K. v1.1** (Caliptra hardware Key Management Block keeping plaintext MEKs out of FW, RFC 9180 HPKE KEM rotated on reset, attested fuse-based Epoch Key crypto-erasure).
- **Link, Fabric & Compliance:** **DMTF SPDM 1.4** (`DSP0274`) over MCTP (`DSP0275`) & PCIe DOE/CMA (keying **PCIe IDE**), **FIPS 140-3** (ISO/IEC 19790/24759, CMVP NAND zeroization & side-channel testing), **NVMe/TCP kTLS 1.3** with DH-HMAC-CHAP / KX-HMAC-CHAP, and **NIST PQC** (FIPS 203/204/205 in NVMe 2.4).
